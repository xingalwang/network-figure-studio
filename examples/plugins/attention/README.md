# Attention 基元与双路并行连接示例

这个插件展示如何扩展**一个独立网络基元**和**一种连接规则**，而不是再增加一个整网模板。代码仅导入 `src/plugins/sdk.ts`，由宿主负责画布、工程 ID、参数回改与撤销。

`primitive.ts` 声明 `example.attention-gate`：输入 `in`、顶部控制端口 `gate`、输出 `out`。通道数、注意力头数是示意标签参数；宽高、2D／立体、厚度、叠层、投影角度、填色、边框、文字、透明度均可调整。它不执行注意力运算，也不推断张量形状。

`connections.ts` 声明 `example.parallel-branches`。依次选择入口、支路一、支路二、合并节点，共四个未锁定的基元；入口和支路需要 `out`，支路需要 `in`，合并节点需要 `in`、`in2`。插件创建：

```text
入口.out → 支路一.in
入口.out → 支路二.in
支路一.out → 合并.in
支路二.out → 合并.in2
```

可用输入层作为入口、两个卷积层作为支路、拼接或相加基元作为合并节点。该模式不自动插入 Attention Gate，不改变节点位置，也不占有后续拓扑；四条线创建后都是普通连线，可独立修改，一次撤销恢复整个连接操作。宿主拒绝范围外端点、缺失端口与重复连接，不会只创建其中一部分。

`index.ts` 把基元放入 `primitives`，把规则放入 `connectionPatterns`。插件已在 `src/builtins/registry.ts` 注册。新增自己的插件时照此组织，再加入同一注册数组；基元会自动进入生成器注册表以支持参数绑定，不要重复声明在 `generators`。

扩展更多控制输入时，在返回节点的 `ports` 中增加稳定名称；扩展更多分支时，修改连接模式的选择顺序、可用性判断和 `ConnectionSpec[]`。如果提供控制点，使用工程世界坐标，宿主会建立 `route.spaceId: null` 的边。连接模式只描述选中节点之间的新边，不直接修改文档或调用画布内部方法。

公开契约与限制见 `docs/plugin-development.md`，工程保存语义见 `docs/project-format.md`。当前接入需要共同开发源码并重新构建，没有在线安装任意插件代码的功能。
